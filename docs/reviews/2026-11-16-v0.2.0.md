  `RA-ARCH-007` and `RA-ARCH-008` (dependency-check), `RA-ARCH-040` (design_code). All four were run. Every
  other `machine` axis is marked **unwired**; its verdict comes from reading the workflow or gate that does the
  job today, and from running that gate locally where it is cheap (cargo-deny, cargo-audit, actionlint,
  `tools/tests`).
- `llm` and `mixed` axes: assessed by reading the code, tests and workflows at the cited lines.
- `manual` axes: marked **needs maintainer**, with what to look at.
- A verdict without evidence is not a pass.
- Security-relevant findings are withheld: their rows say only "details reported privately".
- "Moved" compares with `docs/reviews/2026-11-08-v0.1.9.md`. "new" means the axis was not in that report.

**Top risks**

1. **Fuzzing has never run.**
   - `fuzz.yml` has 2 scheduled runs, and all 7 target jobs failed in both of them.
   - Latest (43704234560, 2026-11-15, after #1334): `cargo fuzz run` builds for `x86_64-unknown-linux-musl`
     and fails with `sanitizer is incompatible with statically linked libc`. The prebuilt `cargo-fuzz@0.13.1`
     from `taiki-e/install-action` (`fuzz.yml:56-58`) defaults `--target` to its own musl build triple.
   - #1334's CI check is `cargo check --cfg fuzzing` on stable (`ci.yml:87`), not the ASan build that the
     weekly job runs. So the PR check is green while the fuzz job fails.
   - A failed scheduled workflow blocks nothing and notifies no one. The `journal_replay` and `trace_parse`
     coverage cited for corruption and parser robustness (`RA-STATE-022`, `RA-SEC-018`) is unit and proptest
     coverage only.
2. **The release side is still absent, now by decision.**
   - Release-side gaps: `RA-CICD-014/017/018/020` (fail), `RA-REL-013/023` (fail) and `RA-CICD-019` (partial).
   - #1338 defers all of them to the first public release (`docs/operations/ci-cd-and-release.md:155`, §6.1;
     #926 moved to v1.0.0): version `0.0.0`, no tags, no `CHANGELOG.md`.
   - The risk is accepted and written down, not unknown. A bug report against a binary cannot name a build:
     `ruse --version` reports `0.0.0`. §6.1's "re-evaluate if" names that trigger.
3. **The context digest has no freshness mechanism.**
   - #1332 brought `spec/CONTEXT.md` up to D-064. Then D-065 and INV-TEXT-TERMINATED landed in the same
     milestone (#1341), and the digest already lags again: the decision list ends at D-064 (`spec/CONTEXT.md:86`),
     and the invariant list `:52-58` has no INV-TEXT-TERMINATED.
   - No check catches this. The generator (#982) is in v0.3.0.
   - `ci-cd-and-release.md:249-255` (§13) still lists `next` and `release/x.y` branches; `next` was dropped
     in #551, and neither exists.
4. **Gate gaps found in the new supply-chain steps.**
   - The Rust-relevance pattern (`ci.yml:47`) does not match `deny.toml`. A PR that changes only the license
     policy skips the license check, and the change is first checked on `main` after merge.
   - `security.yml:35` pipes `git diff … 2>/dev/null | grep -qE`. A failed diff reads as "no manifest change",
     which is the #888 failure mode that `ci.yml` fixed.
   - `cargo-audit` is installed unpinned (`security.yml:48`); `cargo-deny@0.18.9` is pinned (`ci.yml:101`).
5. **Persistence edges are known, documented and filed, but open.**
   - Large files are still read whole (#1290, now in v0.2.4).
   - No journal written by an earlier build is checked in. The 1.0 compat tests build 1.0 records by stripping
     1.1 bytes (`rj01.rs:1151`, `as_v10`) (#1318).
   - RFC-0024 accepts one upgrade loss: a journal over 32 MiB (`DiskBase`) of a file without a final newline
     becomes unreplayable across the upgrade (`RFC-0024-line-terminated-text.md:174-178`).
   - The Emacs profile's `M->` on such a file differs from Emacs (#1343, v0.3.4).
6. **Specs still say more than is enforced, unchanged.** Machine-enforced: 4 of 8 constitution articles,
   3 of 8 fitness functions, 1 of 138 `machine` axes (`gov check`; ratchet `review_machine_unwired` 137/137).
