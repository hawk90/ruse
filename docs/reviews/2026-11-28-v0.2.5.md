**Top risks**

1. **The milestone closes with two of its five stated outcomes undelivered, and its description says
   otherwise.**
   - The description reads: "Fuzz, quarantine, scheduled-failure alerts and spec-to-test links are
     machine-checked; every allowed divergence names an open issue; trace replay round-trips exactly."
   - Delivered: fuzz (#1704, #1718), quarantine (#1715), scheduled-failure alerts (#1721), divergence cites
     (#1702).
   - Not delivered: spec-to-test links and exact trace round-trip. Only their designs landed: RFC-0029 /
     D-070 (#1724) and RFC-0028 / D-069 (#1723), both `decided (design)`. The code issues (#721, #1264,
     #1321) moved to the new milestone v0.2.13 "Traceability" at 05:32 UTC.
   - The v0.2.5 description was not changed after the move (`gh api …/milestones/37`).
2. **Tests and fixtures ran on line 1 only, and fuzzing found it on its first run.**
   - Every CTRL-A test and parity fixture used a one-line or first-line buffer. `incr_number` subtracted
     an absolute offset from a line-relative length (`maxlen`), which is only right on line 1. On every
     later line the number was cut short, and a line start past the line's length panicked (#1714).
   - The first fuzz run that built (Actions run 46111793323, `workflow_dispatch` at `88345206`) failed
     `key_session` only, with that panic. #1725 fixed it, with 5 `i1714` nvim fixtures (all verify), a unit
     test, and the crash input as the seed `fuzz/corpus/key_session/ctrl-a-line-2`.
   - The 20-second PR `fuzz-smoke` passed on #1718 and #1720 with the bug present. The long fuzz job has
     not run since the fix. The next scheduled run is Sunday 2026-11-29 03:00 UTC (`fuzz.yml:12`).
   - The same blind spot may hold for other planners. #1716 (v0.2.12) would re-run every single-line
     fixture one line down. #1719 (v0.3.2) would give `incr_number` one coordinate system.
   - The fix's `maxlen` is now a plain subtraction (`planner/edit.rs:387`). It relies on the number
     starting inside the line, which the commit argues but nothing asserts.
3. **Several new gates check less than their names say.**
   - `divergence_issues.py` (the open-issue check) runs only by hand. CI checks only that a cite is present
     (#1698, v0.2.13).
   - `gov quarantine` sees `#[ignore]` only. A test that skips itself at runtime is invisible to it (#1703,
     v0.2.13).
   - `spec/design-requirements.yaml` does not parse as YAML (PyYAML: "while parsing a block mapping"), and
     `spec-validate` and `docs check` both pass. The new spec YAML path check (#1710) reads the files as
     text. Three `spec/capabilities.yaml` titles are cut short by unquoted commas (#1705, v0.2.13).
   - The scheduled-failure tracker was proved only by `workflow_dispatch` (#1722 opened by run 46118307959,
     closed by run 46118519249). Its real trigger, `workflow_run` on a scheduled run
     (`scheduled-failure.yml:16-18, :38`), has not fired yet: no watched workflow has run on schedule since
     #1721 merged (the last, `perf`, ran at 2026-11-27 16:19 UTC).

1. **Structural doc checks and parallel PRs.** The `module-layout.md` check (#1717) makes the T3 directory
   list an error, not a warning. So a PR that adds a beside-module test directory must also edit the doc,
   and a parallel PR branched before it fails CI until it merges `main`. #1717 itself failed this way on

   `docs check --write` fix the lists the way it fixes the counts?

   one wrong claim. The RFC texts do not record what was corrected, so this report cannot check it. RFC-0025's

   review, with its corrections listed in the RFC, be a required step before an RFC is accepted?

   traceability work moved to v0.2.13 (Top risks 1). Should a re-scope also rewrite the milestone
